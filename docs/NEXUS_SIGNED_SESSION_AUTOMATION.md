# NEXUS provenance and bounded automatic repair (TDOC-12012)
This repository does NOT currently establish that a GitHub token came from ChatGPT, Google AI Studio, Termux, or another browser tab. Identity is not session provenance.
A verified session service (SYNAPSE/aiohttp behind Cloudflare Access) must authenticate the human operator using an actual MFA-enabled IdP, authorize the project session, check an append-only user-visible consented conversation receipt (never hidden chain-of-thought), bind it to repository and exact PR head commit SHA, and post a status `nexus/session-authorized` as a narrowly scoped GitHub App. The GitHub App ID/login must be set as `NEXUS_ATTESTOR_APP_ID` and `NEXUS_ATTESTOR_LOGIN` repository Actions variables. Publishing a status is not 2FA by itself.
Hard enforcement belongs in an ACTIVE GitHub branch ruleset for main: require PR, no force push, minimum one independent review, required checks from CI and `nexus/session-authorized` restricted by GitHub App integration_id. Remove other direct write permissions, personal PAT bypasses, third-party deploy keys with write, and exemptions. Restrict pushes to feature branches separately through access controls; a main-only ruleset does not block all off-branch pushes. The linked ChatGPT/Gemini apps should use separate installed identities, not a shared long-lived PAT.
Automatic CI repair only changes a known Node.js version stanza in two approved workflows on trusted main. Unknown failures are not auto-modified. The generated PR uses the default workflow token; GitHub may not trigger follow-on workflows for PRs generated by GITHUB_TOKEN, so prefer a scoped, approved GitHub App for repair PR creation when configured. Never auto-merge a repair lacking signed-session provenance.
Auto-merge checks for an active branch ruleset, App-pinned provenance check, successful external status on the exact commit, and a distinct human approving review. The GitHub server still decides which required checks are satisfied. Until those protections and the signed-session gateway exist, **auto-merge is intentionally inactive**.
GitHub Admin bootstrap must be done with a separately authorized administrator; current connected GitHub content integration cannot modify rulesets, revoke unrelated credentials, or configure SSO itself.
